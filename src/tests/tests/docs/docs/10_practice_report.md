## Введение
Учебная практика проходила в рамках дисциплины «Осуществление интеграции программных модулей». 
**Тема индивидуального задания:** Разработка учебной операционной системы с расширенной иерархической файловой системой.

**Цель практики:** Получение навыков проектирования, разработки, интеграции и тестирования программных модулей на примере создания симулятора ОС.

## 1. Предметная область
Система **StudyOS** имитирует работу реальной операционной системы. 
-   **Диск:** Роль жесткого диска выполняет база данных SQLite.
-   **Файловая система:** Иерархическая структура на основе таблицы `files` с полем `parent_id`. Поддерживаются операции: создание, чтение, запись, удаление, копирование, перемещение.
-   **Процессы:** Управление через таблицу `processes` с алгоритмом планирования Round Robin.
-   **Безопасность:** Ролевая модель доступа (admin, user, guest) и проверка прав при каждом системном вызове.

## 2. Архитектура системы
Система построена по многослойному принципу (Shell -> Syscalls -> Subsystems -> DB):
1.  **db.py:** Абстракция над SQLite.
2.  **kernel.py:** Управление памятью и сессиями.
3.  **auth.py:** Аутентификация и хэширование (SHA-256).
4.  **fs.py:** Файловая система.
5.  **scheduler.py:** Планировщик процессов.
6.  **syscalls.py:** Системные вызовы (интерфейс).
7.  **shell.py:** Командная оболочка (UI).
8.  **logger.py:** Логирование вызовов.

## 3. Реализованные функции
-   **Файловая система:** `mkdir`, `rmdir`, `touch`, `cat`, `write`, `rm`, `rename`, `copy`, `move`, `cd`, `pwd`, `ls`, `tree`.
-   **Процессы:** `run`, `ps`, `kill`.
-   **Память:** Динамическое выделение, освобождение, жесткий лимит 1024 МБ.
-   **Безопасность:** Запрет удаления чужих файлов, изоляция процессов пользователей.
-   **Логирование:** Полный аудит действий в `syscalls_log`.

## 4. Тестирование
Проведено полное покрытие системы тестами:
-   **Модульное:** db, kernel, auth.
-   **Функциональное:** fs, scheduler, syscalls.
-   **Интеграционное:** Связки модулей.
-   **Системное:** 4 сквозных сценария (SS-01 - SS-04).
-   **Стресс-тестирование:** 10+ процессов, 50+ файлов.

**Итог:** Написано 55+ тестов, покрытие 100%, критических дефектов 0.

## 5. Результаты
Система полностью функциональна. Запускается командой `python -m src.shell`. Дерево каталогов строится корректно, права доступа соблюдаются строго, журнал системных вызовов заполняется в реальном времени.

## 6. Выводы
В ходе практики освоены принципы построения ОС, работа с низкоуровневыми структурами данных через SQL, паттерны проектирования системных вызовов и методика разработки через тестирование (TDD).
